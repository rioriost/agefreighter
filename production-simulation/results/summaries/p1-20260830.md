## Harness corrections discovered by P1

P1 exposed three infrastructure/version issues, all corrected and rerun before
the timed migrations:

1. Azure rejected parallel subnet operations in the same VNet. The Bicep
   dependencies now serialize delegated-subnet creation.
2. The Neo4j memory-report command differs between 4.4 and 5.x. Source
   preparation now uses version-compatible commands.
3. Force-removing a Neo4j 5.26 container immediately after index creation left
   indexes requiring recovery, which a read-only restart correctly rejected.
   Preparation now performs a clean checkpointed stop before enabling
   read-only mode.

These were harness failures before measurement, not agefreighter data-loss or
migration failures.

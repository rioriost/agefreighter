## Reproduced gap and correction

The actual Cosmos iterator, using a bounded fake JSON transport, read wrapped
vertex `score: 1` and flat edge `distance_km: 2` as integers. Previously the
automatic Gremlin path had no schema declaration to retain their intended
floating-point types. The new regression failed before correction with
`declared float lost` and an integer model value. This is a local reproduction,
not a newly observed Azure service incident or a full P1 trial.

Added optional `source.cosmos.gremlin.propertyTypes` and the corresponding
guided-form field. Example: `score=float64,distance_km=float64`.

- Declarations apply after wrapper decoding to matching user properties across
  **all** discovered vertex and edge labels. No per-label precedence, property
  renaming or heuristic type inference was added.
- Reuse the existing checked Cosmos converter for scalars/arrays/nulls. Reject
  incompatible types, integer precision loss and structural/partition fields.
  Missing properties remain absent; unspecified properties retain inference.
- Preserve declarations through both discovery modes and JSON snapshots;
  copy declaration maps rather than aliasing caller state.
- Bind declarations to the source fingerprint; changed types reject an old
  resume token. Absent/empty declarations preserve legacy fingerprints.
- Bound declaration count; reject invalid declarations before discovery calls.
  GUI review is invalidated on editing the type field.

Review: uniform cross-label declarations are sufficient for the P1 `score`
and `distance_km` fields. Sources with conflicting same-name property schemas
must not use a uniform override. Partition-qualified identities remain intact;
discarding partitions to force the existing raw-ID oracle to pass is prohibited.
Existing accepted source configurations, graphs and checkpoints are untouched.

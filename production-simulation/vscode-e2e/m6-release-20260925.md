## Final compatibility corrections

- Build the extension before its unit tests so a clean checkout has the bundle
  needed by the native fixture. Keep compilation failure fatal.
- Use the declared minimum VS Code 1.105.0 in the release workflow, matching
  the extension manifest and ordinary Extension Host CI.
- Preserve the byte-sealed PostgreSQL fixture's LF line endings on Windows.
- Test macOS/POSIX-only qualification helpers on their supported platforms.
  On Windows, verify explicit refusal without weakening directory durability,
  no-replay or deletion protections. Windows interrupted-lock recovery lacks
  the required boot identity; durable directory synchronization is also not
  supported there. These restrictions are documented in the installed guide.
- Update current user guides and distinguish the old design checkpoints from
  implemented and qualified behavior.

## M6 continuation: coverage and guest output bounds

The latest engine CI at `61eeba2` failed the existing 90% product coverage gate
at 86.3%; it was not an extension failure. The continuation preserves the 90%
threshold and restores the documented qualification-tool boundary: newly added
non-shipped `production-simulation` files are listed explicitly alongside the
older exclusions. Architecture tests now enforce the complete exact list and
reject product dependencies on excluded qualification packages.

Additional tests exercise complete source-only PostgreSQL and Neo4j inventory,
JSON/Markdown command output, malformed/close failures, runner admission,
durability, report seals, credential cleanup, migration/resume and read-only
target evidence. The target wire double uses verified TLS and loopback port
5432, fails explicitly on port collision, and is not live database qualification.

These tests found a production defect: embedding `bytes.Buffer` exposed
`ReadFrom`, allowing subprocess pipe copying to bypass the intended output
limit. A private named buffer now keeps all writes bounded. Regressions cover
both stdout and stderr, overflow failure evidence and refusal to replay.
Linux-native tests additionally cover journal exit status, missing or warning
evidence, active workflows, OOM counts and oversized journal output.
This is a Go runner correction after the historical live build, not a claim
that the old archive already contained the fix. The extension bundle and
connector/migration engine implementations are unchanged.

Local `GOFLAGS=-p=2 make check-full` passed with the pinned AGE, PostgreSQL 17,
Neo4j and PostgreSQL 19 Beta 3 services and 90.2% product coverage. An initial
unrestricted race run timed out in the existing SQL/PGQ corruption test;
two isolated repetitions and the complete bounded-concurrency run passed
without changing the timeout or suppressing any test. The full runner suite
also passed natively in an isolated Linux arm64 container. Hosted Linux x64
checks and the protected release gates remain required.

The mutable PostgreSQL `19beta3` tag resolved to a different digest locally.
The harness refused it; validation used the original qualified digest directly,
without changing the pin or claiming qualification of the replacement image.

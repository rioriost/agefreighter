## Source trust-loss correction prepared in this batch

Review exposed a real asynchronous gap: source assessment checked workspace
trust before its native dialog, but did not recheck after approval, during the
workflow-lock wait or immediately before dispatch. The correction checks actual
workspace trust/panel lifetime after the dialog, under the lock, throughout
readiness and after Cosmos admission reads. The backward-compatible optional
dispatch guard also rechecks after command listing, collision GET and durable
intent persistence, immediately before PUT. Readiness dispatch uses the same
guard. Existing callers without this optional callback keep their behavior.

If trust is revoked during persistence, the prewritten `submitted` intent is
retained and the handler refuses before PUT. `submitted` is the existing intent
state, not an HTTP acknowledgement. No command is sent; explicit GET-only 404
reconciliation preserves the intent and cannot replay it. It is not silently
deleted, converted to success or cleared to enable another source read.

Twelve new regressions cover the production panel and actual core dispatch
boundaries; **27 focused TypeScript tests PASS**, typecheck PASS. This is local
evidence, not an assertion that trust was changed in an installed native dialog.
The observer independently passed B07-agent review; B02-agent review covers the
source trust/dispatch change. Installed candidate/UI validation remains pending.

# Observability

Observability is disabled by default. Enabling it never changes command output
on standard output.

## Structured logging

Set `AGEFREIGHTER_LOG_FORMAT` to `json` or `text` to emit command lifecycle
events on standard error. The default and `off` emit no lifecycle logs.
`AGEFREIGHTER_LOG_LEVEL` accepts `debug`, `info`, `warn`, or `error` and
defaults to `info`.

```sh
AGEFREIGHTER_LOG_FORMAT=json agefreighter load job.yaml
```

JSON records use schema version 1 and contain:

| Field | Contract |
|---|---|
| `time` | RFC 3339 timestamp generated by `log/slog` |
| `level` | `INFO`, `WARN`, or `ERROR` |
| `msg` | Stable event name |
| `schema_version` | Logging schema version, currently `1` |
| `event` | `command_started`, `command_completed`, `command_failed`, or `telemetry_export_failed` |
| `service` | `agefreighter` or `agefreighter-tools` |
| `command` | Sanitized top-level command name, when applicable |
| `duration_ms` | Whole milliseconds for completed or failed commands |
| `failed` | Present and `true` for failure events |
| `trace_id`, `span_id` | Present when an OpenTelemetry span is active |

Command arguments, job paths, job IDs, queries, connection strings,
credentials, and error text are intentionally excluded. The original CLI error
is still written separately to standard error for interactive diagnosis.

## OpenTelemetry traces

Set a standard OTLP endpoint to opt in:

```sh
OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:4317 \
  agefreighter load job.yaml
```

The CLI uses the OTLP/gRPC exporter and honors its standard TLS, headers,
compression, timeout, and per-signal endpoint environment variables. Set
`OTEL_TRACES_EXPORTER=otlp` to require an explicit
`OTEL_EXPORTER_OTLP_ENDPOINT`, or `OTEL_TRACES_EXPORTER=none` /
`OTEL_SDK_DISABLED=true` to disable export.

Each invocation emits a `cli.<command>` span. Load and resume commands also emit
a nested `load.execute` span. Attributes are limited to:

- `cli.program`;
- sanitized `cli.command`;
- source type, target type, load mode, and whether the operation is a resume;
- service name, build version, and commit resource attributes;
- success or failure status without the error text.

No command arguments, source records, query text, continuation tokens, or
credentials are attached. Export shutdown is bounded to five seconds. Export
failure does not change a completed migration's exit status; it emits the
generic `telemetry_export_failed` event or message instead.

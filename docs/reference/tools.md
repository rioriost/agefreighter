# agefreighter-tools reference

`agefreighter-tools` contains reproducible fixture, inspection, and benchmark
utilities. It does not mutate loader metadata or production graphs.

## Inspect a load job

```sh
agefreighter-tools inspect JOB
```

`inspect` loads and validates the same versioned job document as the production
CLI, resolves relative source paths, and writes an inspection document with
`formatVersion: 1`.

The source section includes:

- connector type, namespace, and consistency boundary;
- configured read mode, fetch size, page size, and multi-label policy;
- vertex and edge labels;
- source locations such as CSV paths or Cosmos container names;
- identity, resume-key, endpoint, and property source fields.

The target section includes the graph, load mode, property policy, duplicate
policy, and whether the connection is supplied by an environment variable or a
file.

Inspection is offline. It does not contact a source or target and never emits
query text, connection strings, credentials, credential environment-variable
names, or credential file paths. This makes its JSON suitable for diagnostics,
subject to the sensitivity of source file paths and logical database names in
the job itself.

## Run an AGE copy benchmark

```sh
AGEFREIGHTER_AGE_TEST_DSN='postgres://...' \
  agefreighter-tools benchmark-age-copy \
  --workload vertices \
  --strategy direct-text \
  --rows 100000 \
  > run.json
```

The raw result fields are:

| Field | Meaning |
|---|---|
| `workload` | `vertices` or `edges` |
| `strategy` | `direct-text`, `staged-binary`, or `plain-relational` |
| `rows` | Rows written during the sample |
| `propertyBytes` | Generated payload bytes per row |
| `elapsedNanos` | Measured elapsed time |
| `rowsPerSecond` | Throughput derived from rows and elapsed time |
| `walBytes` | PostgreSQL WAL bytes generated by the sample |

## Normalize benchmark reports

```sh
agefreighter-tools benchmark-report [--format json|markdown] [FILE...]
```

With no files, the command reads standard input. A file argument of `-` also
selects standard input and can occur only once. Each input may be either:

- one or more concatenated JSON objects, including JSON Lines; or
- one JSON array of result objects.

Input is limited to 16 MiB and 100,000 records across all files. Unknown fields,
unsupported workload or strategy values, non-positive dimensions, invalid
metrics, and throughput inconsistent with `rows / elapsed` are rejected. The
normalizer does not accept connection or environment metadata.

At most 64 files may be supplied in one invocation, preventing descriptor
exhaustion. Combine larger result sets into JSON Lines before normalization.

The version 1 report groups samples by workload, row count, property size, and
strategy. Each group contains sample count and min, median, and max values for
elapsed nanoseconds, rows per second, and WAL bytes. Integer medians for an even
number of samples use the midpoint rounded down. Groups are sorted by workload,
rows, property bytes, and strategy.

JSON is the default output and is pretty-printed deterministically. Markdown
uses a stable GitHub-flavored table and three decimal places for throughput.
Neither format includes a generation timestamp, so identical inputs produce
identical output.

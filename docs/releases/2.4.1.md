# AGEFreighter 2.4.1

This patch improves the VS Code guided migration workflow. Migration and
verification now have separate, ordered controls, and long-running Azure
operations show their actual phase instead of leaving an ambiguous completion
message.

## Guided workflow fixes

- **5. Migrate** has numbered required actions: AGE preload restart, same-VM
  resize, fresh Linux readiness, and an explicitly approved new migration.
  Optional cost/status tools and recovery actions are grouped separately.
- **6. Verify** imports and evaluates the retained, hash-verified counts report
  without rerunning migration or a verification worker. Full P1 qualification
  remains a separate development-only action, not a requirement for ordinary
  migration counts.
- Private target deployment is monitored with bounded, cancellable, read-only
  status checks after submission and on reconnect. Pending ARM status no longer
  produces a misleading "Ready for the next step" message. Migration preparation
  stays blocked until target provisioning is confirmed.
- Step **5-1** shows PostgreSQL restart progress and waits for both PostgreSQL
  Ready and the applied AGE preload setting. Reconciliation never resubmits an
  uncertain restart.
- Step **5-2** shows working feedback immediately after approval, including price,
  readiness and capacity checks. That single approval starts the bounded
  deallocate, resize and start sequence; no second Start action is needed.
  Cancellation, expiry and uncertain responses stop further sequence steps.
- Target review tolerates the owned runner VM's brief ARM `Updating` state after
  a matching completed readiness receipt using bounded GET-only polling.
  Review errors return immediately to the source panel instead of waiting for
  dismissal of a separate notification.
- Target setup offers discovered free subnet CIDRs, consistent GiB sizing, and
  duration choices of 1, 6 or 12 hours or 1, 2 or 3 days, converted to UTC at
  selection time. Saved deadlines are not silently extended.
- Guided feedback, approved transfer-storage preparation and hash-verified
  assessment report handling give clearer progress and next-step guidance.

## Upgrade and operating boundaries

Install `agefreighter-2.4.1.vsix` from the
[GitHub release](https://github.com/rioriost/agefreighter/releases/tag/v2.4.1).
Marketplace publication is a separate manual action; the GitHub release does
not publish the extension there.

The extension intentionally retains the **2.4.0 Linux runner pin**. Preserve
existing workflow records and their original hash-pinned artifacts. Installing
2.4.1 does not upgrade a runner, replay a command, resume a failed migration,
renew a budget, or authorize a restart, resize or new migration. Cancelling
monitoring does not undo an Azure operation already submitted.

Source-read, cost, scoped-RBAC, ownership and readiness gates remain in force.
Duration choices are authorization deadlines, not automatic shutdown schedules.
The guided target remains private PostgreSQL 18/AGE with HA disabled;
PostgreSQL 19 SQL/PGQ remains a separate experimental advanced workflow.

Regression coverage exercises the actual resize controller and state machine,
ordered action gates, target/restart monitoring, cancellation, expiry and
uncertain acknowledgements. The historical 2.4.0 P1 evidence retains its original
build and scope; it is not a claim of a new full live P1 run for this patch.

Windows CLI archives remain unsigned; verify their checksums and provenance.
macOS archives retain the existing signing and notarization requirements.
See the [installed guide](../../extensions/vscode/README.md) for exact controls
and the existing Windows lifecycle limitations.

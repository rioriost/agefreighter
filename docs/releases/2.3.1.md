# AGEFreighter 2.3.1

Maintenance release for the stable 2.3 line. No 2.4.0 guided-migration
development features are included.

## PostgreSQL floating-point correctness

The PostgreSQL source connector previously inferred number types only from
`row_to_json` output. Native `double precision` / `real` values such as `74.0`
can be serialized as `74` and were incorrectly loaded as integers. Counts and
numeric equality checks do not detect this property-type change.

All three read modes (COPY, cursor, keyset) now describe the original SQL
projection within the shared read-only snapshot and preserve native floating
property types, including arrays and domains. No extra source-data scan is
required. Integer values retain int64 precision; nulls, identity/key spelling,
and JSON/JSONB conversion remain unchanged. NaN and infinities in native float
properties are rejected through the existing malformed-record policy.

This does not add arbitrary-precision decimal support or SQL type inference
inside JSON/composite values. Use an explicit SQL projection/cast if needed.

## Upgrade and recovery

The PostgreSQL source fingerprint changes deliberately. A 2.3.0-or-earlier
PostgreSQL checkpoint is rejected before a source connection is opened; do
not edit checkpoints to bypass this protection. Preserve prior job evidence
and start a new migration against a fresh target. Existing graphs are not
repaired by upgrading the executable. If finishing an old job with its original
binary, independently verify property types before accepting that migration.
Other connectors' fingerprint formats are unchanged.

Regression tests cover integral/fractional floats, signed zero, values above
int64 range, int64 boundaries, nulls, multidimensional arrays, domains,
non-finite rejection, both property-encoding paths, and old-checkpoint refusal.
An end-to-end AGE test checks exact vertex and edge property serialization in
all three PostgreSQL read modes, rather than relying on numeric equality.

The indirect gRPC dependency is updated from 1.83.1 to 1.83.2 to address the
xDS server missing-authority denial-of-service advisory (Dependabot #6).
The stable VSIX is packaged as 2.3.1 with the previously merged
serialize-javascript security update. Windows binaries are provided **without
Authenticode signatures**; macOS signing/notarization and release checksum,
SBOM, and provenance gates remain required. PostgreSQL 19 SQL/PGQ support
remains experimental until GA qualification.

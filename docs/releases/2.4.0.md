# AGEFreighter 2.4.0

The VS Code extension now guides a migration from source setup through private
Azure deployment, execution, recovery and retained verification. The Go engine
runs on a dedicated Linux VM, so the guided workflow needs neither a desktop
CLI nor an initial workspace folder. Existing LoadJob workflows remain available.

## Guided migration

- Configure CSV, Neo4j, PostgreSQL or Azure Cosmos DB for NoSQL. Review typed
  mappings, PostgreSQL catalog/FK suggestions, source placement and private
  connectivity before approving source reads.
- Transfer CSV files with resumable, hash-verified receipts; import complete
  inventories and reports with independent size and checksum checks.
- Review current placement, quota, cost and what-if evidence before creating a
  private PostgreSQL 18/Apache AGE target and resizing the same idle runner VM.
- Start a durable migration explicitly. Reconnect to the same operation after
  VS Code interruption, reconcile uncertain responses without replay, and
  explicitly inspect and resume a failed job.
- Keep counts, integrity and full canonical verification distinct. Failed or
  incomplete evidence cannot become a successful migration report.

Source credentials use protected prompts and transport, with optional
workflow-scoped SecretStorage reuse. Custom Neo4j/PostgreSQL source CA files are
bound to reviewed source settings. AI assistance receives bounded, redacted
evidence and cannot deploy, start, resume or clean up a migration.

Runner subprocess output capture enforces its stdout and stderr bounds even
during optimized pipe copying. Oversized migration report output fails with
retained evidence and cannot authorize automatic replay.

## Qualification and operating boundaries

All nine defined P1 GUI routes and twelve finite extended branches pass.
The fixture contains 1.6 million vertices and 4 million edges. The
[qualification ledger](../../production-simulation/vscode-e2e/progress.md)
retains exact builds, scopes, full reports, failure/recovery evidence and
limitations. These results do not establish arbitrary credential/network
combinations, native Cosmos Gremlin API support or production-scale throughput.

The guided target is a new PostgreSQL 18/AGE server with HA disabled. Existing
network connectivity and a reviewed resource group/subnet are required; no
automatic firewall, VPN or peering changes occur. Long sessions must observe
managed Run Command capacity. Only eligible archived readiness controls have
the built-in removal workflow.

Windows interrupted local-lock recovery is unsupported: this implementation
cannot obtain the required Windows boot identity, so review retains the lock
for manual investigation. Readiness-control removal also fails closed because
POSIX evidence-directory synchronization is unavailable; an archive may remain,
but no cloud DELETE is submitted. Ordinary workflow lock release and read-only
reconciliation are separate operations. See
the [installed guide](../../extensions/vscode/README.md) for these limitations.

PostgreSQL 19 SQL/PGQ remains experimental and separate from the guided target.
Retained Beta 3 evidence does not qualify a PostgreSQL 19 GA build. Windows CLI
archives remain unsigned; verify release checksums and provenance. macOS
archives retain the existing signing and notarization requirements.

## Upgrade

Install the matching VSIX and use the checksum-pinned Linux release selected by
the guided workflow. Preserve existing workflow records, reports and original
runner artifacts for reconnection. Updating the extension does not authorize
restarting, replacing or deleting existing resources, replaying an uncertain
operation, or changing an in-progress job's engine version.

The PostgreSQL property-type correction and checkpoint compatibility rules from
[2.3.1](2.3.1.md) remain in force. Existing graphs are not repaired by updating
the executable. CSV type declarations participate in configuration fingerprints;
changing them invalidates prior resume checkpoints.

## M6 release checks

Final checks cover the engine quality/race/compatibility/recovery gates, native
platform packages, minimum-version Extension Host, shipped dependency audit,
VSIX contents, macOS notarization, checksums, SBOMs, provenance and Homebrew.
GitHub and Marketplace publication are verified separately; a source commit or
a packaged VSIX alone does not prove either publication.

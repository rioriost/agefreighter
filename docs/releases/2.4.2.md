# AGEFreighter 2.4.2

Status: [published as v2.4.2](https://github.com/rioriost/agefreighter/releases/tag/v2.4.2)
on 2026-11-18. The protected
[release workflow](https://github.com/rioriost/agefreighter/actions/runs/44221531718)
passed quality, live Cosmos, macOS signing and notarization, provenance and
Homebrew publication gates.

## PostgreSQL 17 and AGE 1.8

The CLI accepts PostgreSQL 17 with Apache AGE 1.8.x during target admission and
read-only diagnostic probes. PostgreSQL 18 with AGE 1.8.x remains accepted.
Unsupported PostgreSQL/AGE pairings continue to fail before graph changes.

Azure HorizonDB's extension documentation lists AGE 1.8.0 on both PostgreSQL
versions. PostgreSQL 18 and the AGE extension are still marked Preview.
See the [compatibility boundary](../reference/compatibility.md) and
[qualification plan](../../production-simulation/docs/horizondb-parallel-plan.md)
for actual qualification status and scope.

On 2026-11-18, all six source configurations passed against actual Japan East
HorizonDB PostgreSQL 17.11 and 18.6 with AGE 1.8.0: CSV, PostgreSQL 17, Neo4j
4.4.48 and 5.26.30, Cosmos NoSQL, and Gremlin backing documents via NoSQL.
Every route committed exactly 160 vertices and 400 edges, with full canonical
digest comparisons. The 24 selected existing top-level mode/type/recovery
scenarios also passed without skips. The
[retained qualification evidence](../../production-simulation/docs/horizondb-tiny-20261118.json)
does not qualify larger datasets or HA.

HorizonDB Private Link creation hit a provider API-version mismatch. Qualification
used verified TLS and managed identity through a single dedicated NAT IPv4
firewall; public access was disabled afterward. Current pool power APIs return
HTTP 501, so a documented stop operation is not an enforced cost limit.

## Dependencies and operating boundaries

This patch includes the dependency synchronization since 2.4.1 and requires
Go 1.27.4 or newer for source builds.

The extension retains the pinned 2.4.0 Linux runner. Its guided target remains
private PostgreSQL 18 Flexible Server; this patch does not add HorizonDB
provisioning to the wizard, upgrade existing runners, or authorize cloud
operations. Use the updated CLI with an explicitly configured HorizonDB
LoadJob. Existing source consistency and checkpoint compatibility boundaries
are unchanged.

Windows archives remain unsigned; macOS signing, notarization, checksums and
GitHub provenance retain their existing release gates. Marketplace publication
remains separate from the GitHub release.
